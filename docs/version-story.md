# HabitMeter / 寻栖 版本演进

## 总览

HabitMeter 的迭代路径不是单纯堆功能，而是围绕产品成熟度逐步推进：

1. 先验证核心链路能跑通。
2. 再修复稳定性、安全和错误状态。
3. 再增加产品判断力。
4. 最后扩展到多候选比较。
5. Showcase 阶段把项目整理成可以公开展示、可以复述的作品。

## v1.0.0 MVP

目标：跑通居住环境分析的最小闭环。

主要能力：

- 地址 A/B 搜索。
- 高德地图定位。
- 3km 生活圈。
- POI 搜索。
- 四种通勤方式。
- 登录和地址收藏。

这个版本证明了基础数据链路成立：用户输入地址后，产品可以拿到地图、周边和通勤信息。

## v1.0.1 P0 稳定性修复

目标：让项目适合继续迭代和展示。

主要改动：

- 修复 TypeScript build 和 NextAuth session 类型问题。
- 将通勤路线请求改为服务端代理，避免前端暴露 AMap Web Service key。
- 增加环境变量集中校验。
- 增加地图、路线、收藏、地址搜索等关键错误状态。
- 对 POI 做 3km 精确距离过滤。
- 清理 MapContainer 死代码。

产品意义：

P0 解决的是信任问题。用户可以接受某些功能还不完美，但不能接受产品静默失败、无限 loading 或关键配置泄露。

## v1.1.0 P1 居住决策增强

目标：从“展示信息”升级为“给出判断”。

主要改动：

- 新增居住评分模型。
- 新增结论摘要卡。
- 新增 POI 可达性评价。
- 新增通勤推荐。
- 调整桌面和移动端信息架构。
- 增强收藏体验。

产品意义：

P1 让用户不再只看到原始数据，而是看到可解释的结论：总分、等级、优势、短板、推荐通勤方式。

## v1.2.0 P2 多候选对比

目标：从“分析一个地址”升级为“比较一组选项”。

主要改动：

- 新增候选清单。
- 候选数据保存在当前浏览器 localStorage。
- 新增多候选对比引擎。
- 新增对比 UI，包括综合最优和维度优胜。
- 新增偏好模式排序。
- 新增复制对比报告。

产品意义：

P2 更接近真实居住决策。用户可以把多个候选放在同一个比较框架里，而不是依赖记忆和截图。

## Showcase 阶段

目标：把项目从“可运行产品”整理成“可公开展示作品”。

计划内容：

- Showcase-1：公开仓库准备和安全检查。
- Showcase-2：产品案例、演示脚本、版本故事。
- Showcase-3：部署准备和线上运行说明。
- Showcase-4：演示体验打磨和最终验收。

产品意义：

Showcase 阶段不追求大功能，而追求可理解、可演示、可复述。它让别人能够快速看懂这个项目解决什么问题、经历了哪些产品判断、下一步应该如何发展。

## v1.3.0 Showcase Release

目标：完成公开展示版本。

主要改动：

- 仓库公开化和敏感信息检查。
- 产品案例文档。
- 演示脚本。
- 版本演进故事。
- Vercel 部署指南。
- Demo 空状态和候选选择细节打磨。

产品意义：

v1.3.0 不追求新增大型功能，而是让项目更容易被打开、理解、部署和演示。

## v1.3.1 Public Demo

目标：记录公开线上 Demo。

主要改动：

- 将 Vercel Demo 链接加入 README。
- 将线上地址写入部署指南。

## 当前边界

当前版本仍有明确边界：

- 候选清单只保存在当前浏览器。
- 登录收藏依赖 SQLite，本地开发友好，但不适合多实例生产部署。
- 路线结果尚未绘制到地图上。
- 评分模型还没有真实用户数据校准。

这些问题不影响当前版本作为产品原型和展示作品，但应在后续正式产品化阶段继续推进。
