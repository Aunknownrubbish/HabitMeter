## P0-3: 环境变量集中校验

### 问题
`process.env.NEXT_PUBLIC_AMAP_KEY!`、`process.env.AMAP_WEB_KEY` 等分散在 5 个文件中，缺少统一的校验入口。

### 修改文件

| 文件 | 改动 |
|---|---|
| `src/lib/env.ts` | **新建** — `getServerEnv()` (AMAP_WEB_KEY/AUTH_SECRET/DATABASE_URL 校验缓存)、`getAmapWebKey()` (API 路由用)、`getClientAmapConfig()` (地图 JS API 用) |
| `src/lib/amap.ts` | `process.env.NEXT_PUBLIC_AMAP_KEY!` / `NEXT_PUBLIC_AMAP_SECRET!` → `getClientAmapConfig()`；缺失时 throw 明确错误 |
| `src/app/api/route/driving/route.ts` | `process.env.AMAP_WEB_KEY` → `getAmapWebKey()` |
| `src/app/api/route/transit/route.ts` | 同上 |
| `src/app/api/route/walking/route.ts` | 同上 |
| `src/app/api/route/riding/route.ts` | 同上 |

### 校验的环境变量

| 变量 | 校验方式 | 位置 |
|---|---|---|
| `AMAP_WEB_KEY` | `getAmapWebKey()` → null 时 API 返回 500 | `/api/route/*` |
| `AUTH_SECRET` | `getServerEnv()` 校验（NextAuth 内部使用） | `src/lib/env.ts` |
| `DATABASE_URL` | `getServerEnv()` 校验（Prisma 内部使用） | `src/lib/env.ts` |
| `NEXT_PUBLIC_AMAP_KEY` | `getClientAmapConfig()` → null 时 loadAMap 抛出错误 | `src/lib/amap.ts` |
| `NEXT_PUBLIC_AMAP_SECRET` | `getClientAmapConfig()` → null 时 loadAMap 抛出错误 | `src/lib/amap.ts` |

### 验证
- `npm run build` 通过
- `grep process.env.*! src/` → 0 处非空断言
- `AMAP_WEB_KEY` 未放入任何 `NEXT_PUBLIC_` 变量
- 客户端报错可被上层 try/catch 捕获

## P1-1: 新增居住评分模型 v1

### 目标
建立可复用的数据计算能力，将 POI 数量和通勤结果转化为 0-100 居住评分。

### 修改文件
| 文件 | 改动 |
|---|---|
| `src/lib/living-score.ts` | **新建** — 类型定义 (`LivingScore`, `LivingScoreInput`, `LivingScoreBreakdown`, `LivingScoreInsight`) + `calculateLivingScore()` 函数 |

### 评分模型规则

**满分 100，5 个维度：**

| 维度 | 满分 | 评分逻辑 |
|---|---|---|
| 通勤 commute | 35 | 无 addressB 或无通勤结果给 0；优先公交 > 驾车 > 骑行 > 步行。≤30min 满分，≤45min 28，≤60min 21，≤90min 10，>90min 3 |
| 交通 transport | 25 | 地铁 (15) + 公交 (10)。地铁 ≤1000m 是明显优势，公交 ≤500m + 数量多得分高 |
| 便利 convenience | 15 | 最近距离线性评分：≤200m 满分，≤500m 12，≤1000m 8；每 5 个额外 +1 (上限 +3) |
| 医疗 medical | 15 | 最近距离线性评分：≤1000m 满分，≤1500m 13，≤3000m 8，>3000m 低分 |
| 休闲 leisure | 10 | 最近距离线性评分：≤500m 满分，≤1500m 8，≤3000m 4 |

**等级划分：**
- ≥85: excellent (优秀)
- ≥70: good (良好)
- ≥50: average (一般)
- <50: weak (较弱)

**strengths/weaknesses 生成：**
- 根据各维度数据自动生成 2-4 条优势 + 1-3 条短板
- 示例优势："地铁可达性较好 — 最近地铁站约 820m"、"日常补给方便 — 3km 内便利店 18 个"
- 示例短板："医疗资源偏远 — 最近医院约 2.8km"、"通勤压力较高 — 公交约 76 分钟"

### 验证
- `npm run build` 通过
- 纯数据计算模块，未接入 UI
- 无新依赖
