## P0-1: 修复 TypeScript Build 失败 + NextAuth Session 类型泛型化

### 问题

### 修改文件

| 文件 | 改动 |

| `src/lib/auth.ts` | 移除 `(session.user as any).id = token.id as string`，改为 `session.user.id = token.id` |
| `src/components/layout/Sidebar.tsx` | `session` props 从手写类型改为 `import type { Session } from "next-auth"` → `Session \| null` |
| `src/components/layout/MobileDrawer.tsx` | 同上 + 修复 `tab.badge` 的 `as const` 联合类型错误（`"badge" in tab` 窄化） |
| `src/components/auth/AuthPanel.tsx` | `session` props 改为 `Session \| null` |
| `src/components/auth/SavedLocations.tsx` | `session` props 改为 `Session \| null` |
| `src/app/api/locations/route.ts` | 2 处 `(session.user as any).id` → `session.user.id` |
| `src/app/api/locations/[id]/route.ts` | 1 处 `(session.user as any).id` → `session.user.id` |

### 顺带修复的非 session Build 错误

- `Toggle.tsx`: `label` 类型从 `string` 改为 `ReactNode`（调用方传入 JSX 元素）

## P0-2: 通勤路线请求从前端直连改为服务端代理

### 问题
`MapContainer.tsx` 中硬编码了高德 Web 服务 Key (`78cd0cbcc2266dd32961ecf33894fa0e`)，浏览器直接 fetch `https://restapi.amap.com`，Key 暴露在客户端 JS 中。

### 修改文件

| 文件 | 改动 |
|---|---|
| `src/components/map/MapContainer.tsx` | 移除硬编码 `webKey`；4 路 fetch 从 `https://restapi.amap.com/v3/...?key=...` 改为 `/api/route/*?origin=...&destination=...`；数据解析逻辑不变 |
| `src/app/api/route/driving/route.ts` | `process.env.AMAP_WEB_KEY!` → 判空后返回 500 JSON；移除日志 |
| `src/app/api/route/transit/route.ts` | `process.env.AMAP_WEB_KEY!` → 判空后返回 500 JSON |
| `src/app/api/route/walking/route.ts` | `process.env.AMAP_WEB_KEY!` → 判空后返回 500 JSON |
| `src/app/api/route/riding/route.ts` | `process.env.AMAP_WEB_KEY!` → 判空后返回 500 JSON |

### 前后对比

**Before (浏览器直连):**
```ts
const webKey = "78cd0cbcc2266dd32961ecf33894fa0e";
fetch(`https://restapi.amap.com/v3/direction/driving?origin=${origin}&destination=${dest}&key=${webKey}&extensions=all`)
```

**After (本地代理):**
```ts
fetch(`/api/route/driving?origin=${origin}&destination=${dest}`)
```

### 验证
- `npm run build` 通过
- `grep 78cd0cbcc2266dd32961ecf33894fa0e src/` → 无匹配
- `grep restapi.amap.com src/components/` → 无匹配
- `NEXT_PUBLIC_AMAP_KEY` 未改动（地图 JS API 仍需要）
- API 路由：`AMAP_WEB_KEY` 缺失时返回 `{"error":"AMAP_WEB_KEY not configured"}` + 500

## P0-3: 环境变量集中校验

### 问题
`process.env.NEXT_PUBLIC_AMAP_KEY!`、`process.env.AMAP_WEB_KEY` 等分散在 5 个文件中，缺少统一的校验入口。

### 修改文件

| 文件 | 改动 |
|---|---|
| `src/lib/env.ts` | **新建** — `getServerEnv()` (AMAP_WEB_KEY/AUTH_SECRET/DATABASE_URL 校验缓存)、`getAmapWebKey()` (API 路由用)、`getClientAmapConfig()` (地图 JS API 用) |
| `src/lib/amap.ts` | `process.env.NEXT_PUBLIC_AMAP_KEY!` / `NEXT_PUBLIC_AMAP_SECRET!` → `getClientAmapConfig()`；缺失时 throw 明确错误 |
| `src/app/api/route/driving/route.ts` | `process.env.AMAP_WEB_KEY` → `getAmapWebKey()` |
| `src/app/api/route/transit/route.ts` | 同上 |
| `src/app/api/route/walking/route.ts` | 同上 |
| `src/app/api/route/riding/route.ts` | 同上 |

### 校验的环境变量

| 变量 | 校验方式 | 位置 |
|---|---|---|
| `AMAP_WEB_KEY` | `getAmapWebKey()` → null 时 API 返回 500 | `/api/route/*` |
| `AUTH_SECRET` | `getServerEnv()` 校验（NextAuth 内部使用） | `src/lib/env.ts` |
| `DATABASE_URL` | `getServerEnv()` 校验（Prisma 内部使用） | `src/lib/env.ts` |
| `NEXT_PUBLIC_AMAP_KEY` | `getClientAmapConfig()` → null 时 loadAMap 抛出错误 | `src/lib/amap.ts` |
| `NEXT_PUBLIC_AMAP_SECRET` | `getClientAmapConfig()` → null 时 loadAMap 抛出错误 | `src/lib/amap.ts` |

### 验证
- `npm run build` 通过
- `grep process.env.*! src/` → 0 处非空断言
- `AMAP_WEB_KEY` 未放入任何 `NEXT_PUBLIC_` 变量
- 客户端报错可被上层 try/catch 捕获

## P0-4: 补齐关键错误状态

### 问题
- MapContainer 的 4 路路线 fetch 全部 `.catch(() => {})` 静默吞错
- 路线全部失败时 CommutePanel 永远显示"正在计算路线..."
- SavedLocations 收藏/删除失败无反馈
- AddressInput 搜索无结果无提示
- 地图 loadAMap 失败时白屏

### 修改文件

| 文件 | 改动 |
|---|---|
| `src/app/page.tsx` | 新增 `commuteError` 状态 + `handleCommuteError` 回调；传入 sidebarProps 和 MapContainer |
| `src/components/map/MapContainer.tsx` | 新增 `onCommuteError` prop + `mapError` 状态；地图 init `.catch()` 显示错误占位；4 路 fetch 接 `trackRouteDone` 计数器，全部失败时调用 `onCommuteError` |
| `src/components/commute/CommutePanel.tsx` | 新增 `error` prop；loading 结束后优先显示 error，再显示空结果 |
| `src/components/layout/Sidebar.tsx` | 新增 `commuteError` prop，透传 CommutePanel |
| `src/components/layout/MobileDrawer.tsx` | 同上 |
| `src/components/auth/SavedLocations.tsx` | 新增 `error` 状态；handleSave/handleDelete 失败时 setError；JSX 显示错误文案 |
| `src/components/search/AddressInput.tsx` | 新增 `noResults` 状态；搜索完成但无结果时显示"未找到相关地址" |

### 新增错误状态

| 场景 | 状态 | 用户看到 |
|---|---|---|
| 地图 JS API 加载失败 | `mapError` (MapContainer) | "地图加载失败，请检查网络后刷新重试" |
| 4 条路线全部失败 | `commuteError` (page.tsx) | CommutePanel 显示红色 "路线获取失败，请稍后重试" |
| 单条路线失败但其他成功 | 无变化 | 成功路线正常展示 |
| 收藏保存失败 | `error` (SavedLocations) | 红色 "保存失败，请稍后重试" |
| 收藏删除失败 | `error` (SavedLocations) | 红色 "删除失败，请稍后重试" |
| 地址搜索无结果 | `noResults` (AddressInput) | "未找到相关地址" |

### 验证
- `npm run build` 通过
- 成功路径 UI 不变
- 无新依赖
